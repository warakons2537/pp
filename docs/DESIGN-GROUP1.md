## 2. เรื่องที่ 1 — อนุมัติและล็อกผลการเรียน + ประวัติแก้ไข

### 2.1 บทบาทใหม่

- `profiles.role` เพิ่มค่า `academic` (วิชาการ) และ `director` (ผอ.) — ทั้งสองยังทำงานครูได้ตามปกติ (สอน/ประจำชั้น)
- ฟังก์ชันสิทธิ์ใหม่: `is_academic()` = academic หรือ admin · `is_director()` = director หรือ admin
- `is_staff()` ต้องนับสองบทบาทใหม่ด้วย
- หน้า "อนุมัติผู้ใช้" เลือกบทบาทได้ 4 แบบ: ครู / วิชาการ / ผอ. / ผู้ดูแลระบบ

### 2.2 สถานะของรายวิชา-รายภาค

```
ร่าง ──ครูส่ง──► ส่งแล้ว ──วิชาการตรวจผ่าน──► ตรวจแล้ว ──ผอ.อนุมัติ──► อนุมัติแล้ว (ล็อก)
  ▲                │                          │                        │
  └────ส่งกลับ (ต้องใส่เหตุผล)─────────────────┘                        │
  └────────────────ปลดล็อก (ผอ./ผู้ดูแล ต้องใส่เหตุผล)─────────────────┘
```

ตารางใหม่ `course_approvals` (1 แถวต่อ course, ไม่มีแถว = ร่าง)

| คอลัมน์ | ความหมาย |
| --- | --- |
| `course_id` (pk) | รายวิชา-รายภาค |
| `status` | `draft` / `submitted` / `reviewed` / `approved` |
| `submitted_by/at`, `reviewed_by/at`, `approved_by/at` | ใครทำขั้นไหนเมื่อไร |
| `note` | เหตุผลส่งกลับ/ปลดล็อกล่าสุด (ประวัติเต็มอยู่ใน audit) |

กติกา:
- **ครูผู้สอน** กด "ส่งผล" ได้เมื่อสถานะเป็นร่าง · ก่อนส่ง แอปเตือน (ไม่บังคับ) ถ้ามีช่องคะแนนว่าง (`*`) หรือมี 0/ร/มส
- **วิชาการ** กด "ตรวจผ่าน" หรือ "ส่งกลับ" · ทำได้ทีละวิชาหรือติ๊กหลายวิชาพร้อมกัน
- **ผอ.** กด "อนุมัติ" หรือ "ส่งกลับ" · ทำทีละห้อง/ทีละชั้นได้
- ตั้งแต่ **ส่งแล้ว** ขึ้นไป แก้ข้อมูลของ course นั้นไม่ได้ (บังคับในฐานข้อมูล ไม่ใช่แค่ซ่อนปุ่ม):
  `assessment_items`, `item_scores`, `course_results`, `subject_indicators` ผลรายตัวชี้วัด, `period_attendance` ของวิชานั้น, `courses` (สัดส่วน)
  — ใช้ทริกเกอร์ `before insert/update/delete` เรียก `course_locked(course_id)` แล้ว `raise exception` ข้อความภาษาไทย
- **แก้ 0/ร/มส หลังอนุมัติ** ไม่ต้องปลดล็อก: ใช้ระบบซ่อมเดิม (`remedial_cases`) เมื่อซ่อมได้รับอนุมัติ ระบบเขียนผลใหม่ลง `grade_records` (ข้อ 2.3)
- เมนู "วันนี้" ของวิชาการ/ผอ. แสดงจำนวนวิชาที่รอตรวจ/รออนุมัติ

### 2.3 บันทึกผลทางการ `grade_records`

เมื่อผอ. อนุมัติ ระบบ **คัดลอกผลสุดท้าย** ลงตารางนี้ — ปพ.1, ผลสะสม และการเลื่อนชั้นอ่านจากที่นี่ที่เดียว
ตารางเดียวกันนี้รับผลปีก่อนที่นำเข้า/กรอกย้อนหลังด้วย

| คอลัมน์ | ความหมาย |
| --- | --- |
| `id`, `student_id` | |
| `academic_year`, `term`, `level` | เก็บเป็นค่า ไม่ผูกห้อง (ผลปีก่อนไม่มีห้องในระบบ) |
| `subject_code`, `subject_name`, `subject_group`, `subject_type`, `credits`, `hours` | สำเนารายวิชา ณ ตอนอนุมัติ (แก้รายวิชาภายหลังไม่กระทบผลเก่า) |
| `score` | คะแนนรวม (ถ้ามี) |
| `grade` | `4`…`0`, `ร`, `มส`, `ผ`, `มผ` |
| `original_grade` | เกรดก่อนซ่อม (ว่าง = ไม่เคยซ่อม) — ปพ.1 ใช้แสดงว่าผ่านจากการซ่อม |
| `course_id` | มีเมื่อมาจากแอป · ว่างเมื่อนำเข้า/กรอกเอง |
| `source` | `app` / `import` / `manual` |
| `school_name` | ว่าง = โรงเรียนนี้ · มีค่า = ผลจากโรงเรียนเดิม (นักเรียนย้ายเข้า) |

- unique (`student_id`, `academic_year`, `term`, `subject_code`)
- แก้ได้เฉพาะวิชาการ/ผอ./ผู้ดูแล · ทุกการแก้ลง audit

### 2.4 ประวัติการแก้ไข `audit_log`

| คอลัมน์ | ความหมาย |
| --- | --- |
| `at`, `user_id` | เมื่อไร ใคร |
| `table_name`, `row_key` (jsonb) | แก้ตารางไหน แถวไหน |
| `action` | insert / update / delete / submit / review / approve / return / unlock |
| `changes` (jsonb) | เฉพาะคอลัมน์ที่เปลี่ยน `{col: [เดิม, ใหม่]}` |
| `reason` | เหตุผล (ส่งกลับ/ปลดล็อก/แก้ผลทางการ) |

- ทริกเกอร์ทั่วไปตัวเดียวติดกับ: `item_scores`, `assessment_items`, `course_results`, `courses`, `course_approvals`, `grade_records`, `remedial_cases`
- เก็บเฉพาะส่วนต่างเพื่อประหยัดพื้นที่ (แผนฟรี 500 MB) · ประเมิน ~1–2 แสนแถว/ปี ≈ 30–60 MB
- อ่านได้: ผู้ดูแล/ผอ./วิชาการ ทั้งหมด · ครู เฉพาะวิชาที่ตัวเองสอน · ไม่มีใครแก้/ลบได้ (ไม่มี policy update/delete)
- หน้าจอ: ปุ่ม "ประวัติ" ในหน้าคะแนนรายวิชา และหน้า "ประวัติการแก้ไข" ของผู้ดูแล (กรองตามวิชา/คน/วันที่) · พิมพ์ A4 ได้

## 3. เรื่องที่ 2 — ผลการเรียนสะสม (GPAX) + ตรวจเกณฑ์จบ

### 3.1 คำนวณ

- ช่วงชั้น: **ประถม** = ป.1–ป.6 · **ม.ต้น** = ม.1–ม.3 (สะสมแยกกัน)
- อ่านจาก `grade_records` ของนักเรียนในช่วงชั้นนั้น
- GPAX = Σ(เกรด × น้ำหนัก) ÷ Σน้ำหนัก ใช้ `gpa()` เดิม (ไม่นับ ร/มส/ผ/มผ, ปัดทิ้ง 2 ตำแหน่ง)
- น้ำหนัก: ม.ต้น = หน่วยกิต · ประถม = ชั่วโมง ÷ 40 (ตาม `weightOf()` เดิม)
- แสดงเพิ่ม: GPA รายปี, GPA รายกลุ่มสาระ 8 กลุ่ม (ใช้ใน ปพ.1), หน่วยกิต/ชั่วโมงที่ "ได้" (เกรด ≥ 1) แยกพื้นฐาน/เพิ่มเติม

### 3.2 เกณฑ์จบ (หลักสูตรแกนกลาง 2551 — โรงเรียนยังใช้หลักสูตรเดิม)

ตั้งค่าเป็นตัวเลขใน "ตั้งค่าระบบ → เกณฑ์การจบ" (เก็บใน `school_settings.graduation_rules` jsonb) ค่าเริ่มต้น:

| เกณฑ์ | ประถม (ป.6) | ม.ต้น (ม.3) |
| --- | --- | --- |
| รายวิชาพื้นฐาน | ผ่านทุกวิชา (ไม่มี 0/ร/มส ค้าง) | ได้ ≥ 66 หน่วยกิต |
| รายวิชาเพิ่มเติม | ผ่านตามที่โรงเรียนกำหนด | ได้ ≥ 11 หน่วยกิต (รวม ≥ 77) |
| อ่าน คิดวิเคราะห์ เขียน | ผ่าน | ผ่าน |
| คุณลักษณะอันพึงประสงค์ | ผ่าน | ผ่าน |
| กิจกรรมพัฒนาผู้เรียน | ผ่าน | ผ่าน |

- ผลตรวจแสดงเป็นรายการ ✓/✗ ต่อคน พร้อมบอกว่าขาดอะไร (เช่น "ค 22102 ภาค 2/2568 ได้ 0 ยังไม่ซ่อม")
- ⚠️ ตัวเลขข้างต้นเป็นค่าเริ่มต้นจากหลักสูตร **ต้องเทียบกับระเบียบการวัดผลของโรงเรียน** ก่อนใช้จริง

### 3.3 ได้ผลปีก่อนมาอย่างไร (ทั้ง 2 แบบ)

1. **นำเข้าจากไฟล์ผลสัมฤทธิ์เดิม** — ใช้ตัวอ่านเดิม (`js/achievement-import.js`) แต่ **เขียนลง `grade_records` (source = import)** โดยไม่สร้างห้อง/รายวิชา/คะแนนรายช่อง
   - จับคู่นักเรียนด้วยเลขประจำตัว → ชื่อ-สกุล · แสดงตารางตรวจก่อนบันทึก (คนที่จับคู่ไม่ได้ / ผลซ้ำกับที่มีแล้ว)
   - ปี/ภาค/ชั้น อ่านจากไฟล์ ถ้าอ่านไม่ได้ให้เลือกเอง
2. **กรอกย้อนหลัง** — หน้า "ผลการเรียนย้อนหลัง" เลือก นักเรียน + ปี + ภาค → ตารางรายวิชา (เลือกจาก `subjects` หรือพิมพ์รหัส/ชื่อ/หน่วยกิตเอง) + เกรด · ช่อง "โรงเรียนเดิม" สำหรับนักเรียนย้ายเข้า
   - ทางลัด: กรอกทั้งห้องทีละวิชา (แบบตาราง Excel) สำหรับรุ่นที่ยังไม่มีไฟล์

## 4. เรื่องที่ 3 — เลื่อนชั้น / จบการศึกษา / ขึ้นปีการศึกษาใหม่

### 4.1 ตัวช่วย "ขึ้นปีการศึกษาใหม่" (ผู้ดูแล) — 4 ขั้น

1. **ตรวจความพร้อม** — รายวิชาของปีนี้ที่ยังไม่อนุมัติ (รายชื่อ + ลิงก์) · ไปต่อได้ แต่ขึ้นคำเตือนชัด
2. **ตัดสินรายคน** — ตารางทุกห้อง ทุกคน แอปเสนอผลให้ก่อน ครูประจำชั้น/วิชาการแก้ได้ (ต้องใส่เหตุผลเมื่อต่างจากที่แอปเสนอ)
   - `เลื่อนชั้น` · `ซ้ำชั้น` · `จบการศึกษา` (ป.6, ม.3) · `จบอนุบาล` (อ.3) · `ย้ายออก`
   - ข้อเสนอเริ่มต้น (ตั้งค่าได้): ม.ต้น เลื่อนเมื่อผ่านรายวิชาพื้นฐาน + ผ่านการประเมินอื่น + GPA ปีนั้น ≥ 1.00 · ประถม เลื่อนเมื่อเวลาเรียน ≥ 80% และผ่านรายวิชาพื้นฐาน · ชั้นจบ = ผลตรวจเกณฑ์จบ (ข้อ 3.2)
   - มี 0/ร/มส ค้าง → แสดงเป็น "รอซ่อม" ไม่ใช่ซ้ำชั้นอัตโนมัติ
3. **ผอ. อนุมัติผลการตัดสิน** — พิมพ์ "รายงานผลการเลื่อนชั้น/จบ" A4 สำหรับลงนาม
4. **สร้างปีใหม่** — กดครั้งเดียว:
   - สร้าง `terms` ปีถัดไป ภาค 1 (และภาค 2)
   - สร้าง `classrooms` ปีใหม่ (คัดลอกห้องเดิม + เลือกคัดลอกครูประจำชั้นได้)
   - สร้าง `enrollments` ปีใหม่: เลื่อนชั้น → ห้องชั้นถัดไป · ซ้ำชั้น → ชั้นเดิม · เรียงเลขที่ใหม่ตามเลขที่เดิม
   - จบ → `students.status = 'graduated'` · ย้ายออก → `moved`
   - **ไม่**คัดลอกการเปิดสอนรายวิชาอัตโนมัติ (ให้ไปเปิดสอนตามปกติ หรือปุ่ม "คัดลอกการเปิดสอนจากปีก่อน" แยกต่างหาก)
   - **ไม่**ตั้งปีใหม่เป็นปีปัจจุบันทันที ผู้ดูแลเลือกเองเมื่อพร้อม

### 4.2 ตารางใหม่ `promotions`

| คอลัมน์ | ความหมาย |
| --- | --- |
| `student_id`, `academic_year`, `level` | ปี/ชั้นที่ตัดสิน |
| `decision` | promote / repeat / graduate / leave |
| `suggested` | สิ่งที่แอปเสนอ (ไว้เทียบ) |
| `reason`, `decided_by` | เหตุผลเมื่อแก้ต่างจากข้อเสนอ |
| `approved_by/at` | ผอ. อนุมัติ |
| `graduated_on` | วันอนุมัติจบ (ใช้ใน ปพ.1/ปพ.3) |
| `run_id` | รอบที่สร้างปีใหม่ — ใช้ **ย้อนกลับ** ได้ ถ้าปีใหม่ยังไม่มีข้อมูลเช็กชื่อ/คะแนน |

## 5. เรื่องที่ 4 — ปพ.1 และ ปพ.3 (แอปวาดเอง)

### 5.1 ปพ.1 ระเบียนแสดงผลการเรียน (ป.6 และ ม.3)

- รูปแบบตามแบบฟอร์มกระทรวง หลักสูตรแกนกลาง 2551 (ปพ.1:ป และ ปพ.1:บ) หน้า A4 วาดแบบเดียวกับ ปพ.6 ปัจจุบัน (ฟอนต์ TH SarabunPSK)
- ข้อมูลที่ใช้ / ต้องเพิ่ม:

| ส่วน | มาจาก |
| --- | --- |
| ชื่อโรงเรียน สังกัด ที่ตั้ง | `school_settings` (มีแล้ว) |
| ชื่อ-สกุล เลขประจำตัว เลขประชาชน วันเกิด เพศ สัญชาติ ศาสนา ชื่อบิดา-มารดา | `students` + `student_private` (มีแล้ว) |
| วันเข้าเรียน · โรงเรียนเดิม · ชั้นที่เข้า | **เพิ่ม** `student_private.admission` jsonb |
| ผลรายวิชาทุกปีทุกภาค เรียงตามปี/ภาค | `grade_records` |

| ผลอ่านคิดวิเคราะห์ · คุณลักษณะ · กิจกรรม | ผลสรุปช่วงชั้น (ค่าล่าสุดของชั้นจบ จาก `trait_scores` / `activity_results`) |

| ผู้ลงนาม | นายทะเบียน + ผอ. จาก `school_settings` |

- พิมพ์ได้ทั้ง **ฟอร์มเปล่าเต็มหน้า** (กระดาษ A4 ธรรมดา) และ **พิมพ์ทับแบบฟอร์มจริง** (ซ่อนเส้น/หัวฟอร์ม เหลือแต่ข้อมูล) — ขั้นหลังเป็นงานรอบถัดไปเมื่อได้แบบฟอร์มจริงมาวัดตำแหน่ง
- ไม่มีรูปถ่ายในรอบแรก (เว้นกรอบไว้ติดรูป)

## 6. เรื่องที่ 5 — ระดับอนุบาล

ตรวจโค้ดแล้ว: ห้อง อ.1–อ.3 สร้างได้ (`LEVELS`), DMC นำเข้าได้, เช็กชื่อ/น้ำหนัก-ส่วนสูงใช้ได้ตามปกติ **แต่ไม่มีการประเมินพัฒนาการ** (มีแค่คำว่า "พัฒนาการ" ในแบบประเมินสมรรถนะ)

ออกแบบ (หลักสูตรการศึกษาปฐมวัย 2560):
- ประเมิน **4 ด้าน** — ร่างกาย / อารมณ์-จิตใจ / สังคม / สติปัญญา → 12 มาตรฐาน → ตัวบ่งชี้ → สภาพที่พึงประสงค์ตามอายุ
- ระดับคุณภาพ 3 ระดับ: 3 = ดี · 2 = พอใช้ · 1 = ควรส่งเสริม · ประเมินภาคละครั้ง (หรือตามที่โรงเรียนตั้ง)
- เก็บในตาราง `assess_detail` เดิม (เพิ่มค่า `form = 'early_dev'` ใน check) — รายการมาตรฐาน/ตัวบ่งชี้ทำเป็นไฟล์ข้อมูลใน `js/assess-forms.js` แบบเดียวกับแบบประเมินละเอียด
- สรุปรายด้าน = ฐานนิยม (ใช้ `modeSummary()` ใน `js/assess.js`)
- **สมุดรายงานประจำตัวเด็ก** (A4 รายคน): ข้อมูลเด็ก · เวลาเรียน · น้ำหนัก-ส่วนสูง (มีแล้ว) · ผลพัฒนาการ 4 ด้าน รายภาค · ความเห็นครู (`homeroom_comments` มีแล้ว)
- ไม่ใช้เกรด/GPA และไม่เข้าระบบล็อกผลรายวิชา (ใช้การล็อกรายห้องรายภาคแบบง่ายแทน ถ้าต้องการ)
- ⚠️ ขอไฟล์แบบประเมินพัฒนาการ/สมุดรายงานที่ครูอนุบาลใช้อยู่ เพื่อให้รายการตัวบ่งชี้และหน้าตาตรงของจริง
